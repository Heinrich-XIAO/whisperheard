# whisperheard

A transformer that was **never trained**, then **completely reverse-engineered,
with every finding a machine-checked theorem**, in **pure Lean 4**: core Lean only,
no Mathlib, no Python, no floating point.

The network is a 2-layer, attention-only transformer with integer weights.
Its weights were written by hand and then hidden behind a random integer
change of basis, so the raw matrices are dense and unreadable (962 of 1160
weights are nonzero). Everything below was then recovered from those raw
numbers and proved in Lean. That covers what the network computes on every
input, how it computes it, what every component is for, what is redundant,
how much margin it has, and what can and cannot be read off the weights.

```
$ lake exe whisperheard 2 0 3 1 2 0 3 3 1 2 1 0
  pos  tok  head1→  head2→            logits  pred  law
    0    2       0       0      [0, 0, 5, 0]     2    2
    1    0       0       1      [5, 0, 0, 0]     0    0
    2    3       1       2      [0, 0, 0, 5]     3    3
    3    1       2       3      [0, 5, 0, 0]     1    1
    4    2       3       1      [5, 0, 0, 0]     0    0
    ...
   11    0       0       6      [0, 0, 0, 5]     3    3
network = law at every position (as proved: predict_whisper)
```

## Build

```sh
lake build                          # checks every proof (≈1 min)
lake exe whisperheard 3 1 2 3 1     # run the real network on any input
lake env lean scripts/Audit.lean    # axioms behind the headline theorems
```

Toolchain: Lean `v4.36.0` (see `lean-toolchain`). The headline theorems
depend only on `propext`, `Quot.sound` and `Classical.choice`. There is no
`sorry`, and no `native_decide`: every computation is checked by the kernel
(`decide +kernel`).

## The network

| | |
|---|---|
| vocabulary | 4 tokens (`0 1 2 3`) |
| context window | 8 learned positions |
| residual width | 20 |
| layers | 2 attention heads (one per layer), no MLPs, no LayerNorm, no biases |
| attention | causal, **hard**: each query attends to the single highest-scoring key; ties go to the earliest key |
| prediction | argmax of the logits (ties go to the lowest token) |
| weights | integers, generated by `scripts/Gen.lean` (pure Lean, seeded, no training) |

The forward pass (`Whisperheard/Model.lean`) is an obviously standard,
deliberately naive specification. `Whisperheard/Fast.lean` is a fast
evaluator, **proved equal** to it (`Fast.predict_eq`), which the CLI uses.

## What it computes: the complete law

> **`predict_whisper_total`.** For *every* stream `x : ℕ → ℕ` and every
> position `i`:
>
> ```
> whisper.predict x i =
>   let a := if x i < 4 then target 8 x i else 0
>   if x a < 4 then x a else 0
> ```
>
> where `target 8 x i` searches `j = r, r-1, …, 1` (with `r = min i 7`) for
> the latest `j` with `x (j-1) = x i`, and defaults to `r`.

For in-vocabulary inputs this simplifies to `predict x i = x (target 8 x i)`
(`predict_whisper`). In words:

* **Induction.** If the current token appeared before, and its latest
  earlier occurrence is at `k`, predict the token that followed it,
  `x (k+1)` (`predict_induction`).
* **Default: repeat.** A token never seen before is predicted to repeat
  (`predict_fresh`).
* **Beyond the window** (`i ≥ 8`) the network still does induction, but
  only over the first eight tokens. The search runs over `x 0 … x 6`, and the
  default becomes `x 7` (`predict_beyond`).
* **Out-of-vocabulary tokens** embed to the zero vector. An out-of-vocabulary
  query switches head 2 off (it attends to position 0), and an out-of-vocabulary
  attended token writes nothing (all logits 0, so the output is `0`).
* **Causal** (`predict_causal`) and **equivariant under any relabelling of
  the vocabulary** (`predict_equivariant`). Equivariance is invisible in the
  raw weights and immediate from the law.
* **Exact logits.** `5` on the predicted token and exactly `0` on the other
  three (`logits_whisper`). Every other path cancels exactly.

### Generation dynamics

Feed the network its own predictions (`Interp/Generation.lean`). Past
position 8, generation is a fixed map `F` on the four tokens, determined by
the first eight tokens (`gen_recurrence`). So, from **any** nonempty
in-vocabulary prompt, greedy
generation is **eventually periodic with period 1, 2, 3 or 4**, from
position `max (|prompt| - 1) 8 + 3` on (`gen_periodic`).

## How it computes it: the mechanism

**1. The residual basis.** Twenty vectors can be read straight off the raw
weights: the 4 token embeddings `T t`, the 8 position embeddings `P p`,
head 1's outputs `S t = OV₁(T t)`, and head 2's outputs `O t = OV₂(T t)`.
`scripts/Discover.lean` inverts the matrix they form, exactly over ℚ. The
kernel then checks that the inverse is an integer two-sided inverse
(`Binv_mul_B`, `B_mul_Binv`). So these twenty directions are a **ℤ-basis**
of the residual stream.

**2. Every circuit, in closed form, on arbitrary residual vectors**
(`Interp/Basis.lean`, with `c(u)` the coordinates):

| circuit | closed form | nonzeros |
|---|---|---|
| head 1 QK | `qk₁(u,v) = 4 · Σ_{p=1}^{7} c(u)_{P p} · c(v)_{P (p-1)}` | 7 |
| head 1 OV | moves the token block into the `S` block; kills everything else | 4 |
| head 2 QK | `qk₂(u,v) = Σ_t c(u)_{T t} · (10 · c(v)_{S t} + Σ_p w(p) · c(v)_{P p})`, `w(0) = -10`, `w(p) = p` | 36 |
| head 2 OV | moves the token block into the `O` block; kills everything else | 4 |
| unembedding | `logit_t(u) = 5 · c(u)_{O t}` | 4 |

**55 integers describe the entire network.** `Interp/Decompiled.lean`
writes them back as a sparse 67-weight network (factored per head) and
proves it **computes exactly the same function** as the 962-nonzero raw one
(`decompiled_eq`).

**3. What each piece does** (`Interp/Mechanism.lean`, `Interp/Whisper.lean`):

* **Head 1 is a previous-token head.** Its scores depend only on positions:
  `4` on `i-1`, `0` elsewhere. It attends to `i-1` inside the window and to
  `0` beyond it, and ignores tokens entirely (`attn1_whisper_total`). It
  copies the attended token into the `S` slot.
* **Head 2 is an induction head**, via **K-composition only**. Its query
  reads the current token; its key reads head 1's output (score `+10` if
  the key's previous token equals the query's token) plus a positional
  ramp `w`. Its queries and values ignore head 1's output (no Q- or
  V-composition: `no_q_composition`, `no_v_composition`). It copies the
  attended token into the `O` slot.
* **Only one path reaches the logits.** The direct path, head 1's output and
  the positional embeddings contribute exactly `0` (`only_head2_path`).

The reduction from tables to behaviour is proved **once, generically**
(`Spec.predict_formula`). Any network satisfying the circuit tables, with
symbolic constants, computes
`predict x i = x(argmax_{j≤i} (cm·[x i = x (prev j)] + w j))`. The rest is
combinatorics (`argmax_score2_eq_target`).

## What every part is for: ablations

All ablations are weight edits. The ones that delete a single feature
direction use the recovered basis. Each edited network gets fresh
kernel-checked circuit tables (`Interp/Ablations.lean`).

| edit | effect |
|---|---|
| zero head 1's output | **echoes**: predicts `x (min i 7)`; induction is gone (`noHead1_law`) |
| zero head 2's output | **constant**: always predicts `0` (`noHead2_law`) |
| blind head 2's keys to position (remove the ramp) | every match ties and the first one wins, so recency is lost: on `0 1 0 2 0` it outputs `0`, not `2` (`noRamp_breaks`) |
| blind head 2's keys to position 0 only (remove the `-10`) | **no change on any input** (`noSuppress_same`) |
| replace the match strength `10` by `c` | obeys the law on every valid input **iff `c ≥ 6`** (`frontier`) |

## Findings that were not designed in

The in-window induction behaviour was built on purpose. These were found
afterwards:

1. **The `-10` on position 0 is dead weight.** It was meant to stop a
   spurious match at position 0. But whenever position 0 could match,
   position 1 is a genuine match that already outscores it.
2. **The match strength has a safety margin of exactly 4.** `10` could be
   `6`. At exactly `6` the network survives only because ties go to the
   earliest key.
3. **The beyond-window behaviour** (induction over the first eight tokens,
   defaulting to `x 7`) is an emergent consequence of positions ≥ 8 having
   zero embeddings.
4. **On in-vocabulary inputs, tie-breaking is consulted in exactly one
   place.** Head 1 has a unique maximum inside the window (margin 4:
   `head1_margin`). Head 2 never ties (`head2_unique`), and the predicted
   token leads by 5 (`logit_margin`). But past the window, every head-1 key
   scores `0` (`head1_total_tie`), so the "earliest key" convention decides.
   (Out-of-vocabulary tokens add two more total ties, both described by the
   total law.)
5. **Head 2's recency margin is 1** (`head2_margin_tight`): two adjacent
   matches differ by a single unit of the ramp.
6. **Generation always falls into a cycle of length ≤ 4.**
7. **The weights cannot say more than this.** Heads matter only through
   their QK form and OV map (`predict_congr`). Head-internal bases are
   pure gauge (`qk_gauge`, `ov_gauge`). So is the residual basis
   (`conj_predict`), which also certifies that the obfuscation in
   `Gen.lean` changed nothing.

## What "nothing left to discover" means here

* **Behaviour:** the output is known exactly, as a closed formula, on every
  input stream (any natural numbers, any length) and at every position.
* **Internals:** both attention patterns and the exact logits are known at
  every position, on every input. So is the residual stream after each layer,
  as an exact sum of named feature vectors (`resid1_whisper`,
  `resid2_whisper`).
* **Weights:** every weight-level circuit is given in closed form in a basis
  recovered from the weights. That description is complete up to symmetries,
  each of which is proved to be a symmetry.
* **Necessity:** every component is either shown necessary (an ablation
  breaks the law) or proved redundant. The one tunable strength has its
  exact frontier.

Outside the model as defined, and so not covered: softmax attention (this
network uses hard attention) and other tie-breaking conventions.
